peetsfea patch plan

0.3.8.x ferrite range and full-solve hardening

이 문서는 0.3.8.x에서 판단할 두 변경, 즉 TX MULL ferrite sheet count 5장 확장과 4-core full solve 해석 설정 강화를 한 곳에 고정한다. semi_dry 경로는 제거하고, baseline 대비 solve 시간이 얼마나 증가하는지는 후속 작업에서 실제 headless HFSS 실행으로 측정해 기록한다.

요약 패치 범위 입력 파라미터 출력 파라미터 해석 설정 작업 순서 완료 기준

1. 요약

변경 1 ferrite range

ferrite.tx_mull_sheet_count를 기존 1..3에서 1..5로 확장한다. 자유변수 개수는 그대로 18개다.

변경 2 full solve only

semi_dry 경로를 제거하고 full solve 설정을 MaxDeltaS=0.003, pass 16/13/9, PercentRefinement=30으로 강화한다.

판단 자료 timing follow-up

직전 baseline commit eb7f18a와 변경 worktree를 같은 fixed TOML, 같은 seed, 같은 4-core CPU 설정으로 돌리는 시간 비교는 후속 작업으로 남긴다.

0.3.8.x의 기본 형상 자유 입력은 18개다. RX 모드와 RX normal-coil quarter-turn 변수 3개는 고정되어 입력 벡터에서 빠진다.
측정 원칙: 두 실행은 모두 cores=4, gpus=0으로 고정한다. 가능하면 동시에 실행하고, 결과에는 solve_outcome.analyze_elapsed_ms와 solve_telemetry.elapsed_ms를 모두 남긴다.

2. 패치 범위

영역0.3.8.0에서 할 일비고
Version/spec pyproject.toml, version.py, ssw_design_space.py, ssw_step.py, package data TOML의 버전 표기를 0.3.8.0으로 맞춘다. runner 문서의 peetsfea.__version__ 계약도 같이 갱신한다.
Geometry validation TX/RX SSW의 long-dimension Y-axis 검증 블록을 삭제한다. thin-plane 검증은 유지한다. TX는 XY-plane thin Z, RX는 YZ-plane thin X 조건만 불변식으로 남긴다.
Design space RX SSW mode와 RX no-SSW quarter-turn 변수를 count=1로 고정한다. 고정값: is_ssw_enabled=1, no_ssw_qturn_start_int=0, no_ssw_qturn_n_int=0.
TX ferrite range ferrite.tx_mull_sheet_count의 reference sweep을 [true, 1, 5, 5]로 확장한다. 입력 차원은 18개 그대로다. 샘플러 후보 수만 1/2/3장에서 1/2/3/4/5장으로 넓어진다.
Full solve settings MaxDeltaS=0.003, pass 16/13/9, PercentRefinement=30을 적용한다. AEDT payload의 MaxPass/MinPass/MinConvPass alias도 같은 pass 값으로 맞춘다.
Runner mode semi_dry mode를 제거하고 full만 허용한다. 빠른 테스트용 pass override는 backend 함수 단위 테스트로만 남기고 runner-facing 경로에서는 쓰지 않는다.
Solve time report baseline과 변경 버전을 같은 fixed point로 headless HFSS solve한다. 이번 커밋 이후 후속 작업으로 실행하고 이 HTML에 시간 차이를 기록한다.
Tests/docs dimension count, fixed 값, ferrite sheet count, token/ledger 기대값, RX normal-mode 테스트를 새 계약으로 갱신한다. RX normal/spiral 선택 테스트는 0.3.8.x에서는 제거하거나 거부 테스트로 바꾼다.

5. 해석 설정 강화 및 후속 시간 비교

이 섹션은 PyAEDT SSW 경로의 HFSS setup/mesh/pass 설정 변경과 baseline 대비 solve 시간 증가량을 판단용으로 정리한다. 시간 비교는 이번 규약 커밋 이후 후속 작업으로 실행한다. 값의 소스는 src/peetsfea/backend/pyaedt/ssw_ports.py다.

5.1 Mesh assignment

항목현재값의미 / 강화 판단 포인트
Module / operationMeshSetup / AssignLengthOp / Length1명시 length mesh operation 1개를 기록된 대상에 적용한다.
Mesh 대상RX copper, TX copper, all FR4 PCB bodies현재는 TX/RX 주요 copper와 FR4에만 length 제한을 건다. ferrite, air region, port sheet는 직접 mesh target이 아니다.
RX copper 후보rx_ssw_coil_coil_copper 또는 rx_ssw_coil_ssw_copper실제 ledger에서 정확히 1개가 잡혀야 한다. 0개/2개면 fail-fast.
TX copper 대상tx_ssw_coil_ssw_copper실제 ledger에서 정확히 1개가 잡혀야 한다.
FR4 대상recorded fr4_body_names 전체최소 1개가 필요하다.
RefineInsidefalse현재 length operation은 내부 refine을 켜지 않는다.
RestrictLength / MaxLengthtrue / 1mm가장 직접적인 mesh 강화 축이다. 예: 0.75 mm, 0.5 mm로 낮추면 edge/skin 근방 해상도는 올라가고 solve time은 증가한다.
RestrictElem / NumMaxElemtrue / 50000mesh 증가 상한이다. length를 줄일 때 같이 올릴지 판단해야 한다.

7. 완료 기준

  • peetsfea.__version__, SUPPORTED_SPEC_VERSION, SPEC_VERSION, and package TOML spec_version are all 0.3.8.0.
  • check_ssw_toml_in_design_space(DEFAULT_SOURCE_TOML_PATH, DEFAULT_REFERENCE_TOML_PATH) reports dimension_count == 18.
  • free_owner_paths does not contain rx_ssw_coil.is_ssw_enabled, rx_ssw_coil.no_ssw_qturn_start_int, or rx_ssw_coil.no_ssw_qturn_n_int.
  • ferrite.tx_mull_sheet_count is still one free owner path, with integer sampled values allowed from 1 through 5.
  • semi_dry is not an accepted runner-facing report mode.
  • Full solve setup uses MaxDeltaS=0.003, pass 16/13/9, and PercentRefinement=30.
  • Baseline vs changed solve-time comparison is explicitly deferred to a follow-up task.
  • Generated STEP and ledger identify TX/RX as SSW geometry; RX normal spiral copper is not a valid 0.3.8.x output.
  • Raw report contract still exports Results1_Pass, Results2_Last, and Results3_Freq.
  • All changed tests pass from run/ using ../.venv/bin/pytest.
  • ../.venv/bin/pyright ../src ../entry ../tests has no diagnostics.
  • Because this changes STEP/AEDT-facing geometry behavior, a real headless AEDT validation is run from run/. If AEDT or license is unavailable, the release remains explicitly incomplete.
0.3.8.0의 핵심 판단 기준은 "보기 위해 임시로 통과"가 아니라, 버전/spec/test/report/AEDT 검증까지 새 형상 계약으로 일관되게 닫히는 것이다.
