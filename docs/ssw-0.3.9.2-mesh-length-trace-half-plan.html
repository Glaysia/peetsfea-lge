SSW 메시 길이 계획 — 트레이스 너비 절반 기반 적응형 (0.3.9.2)

0.3.9.2의 메시·setup·sweep은 GUI에서 검증한 녹화본 tmp/mesh_pass.py를 그대로 기준으로 삼는다. 단 하나의 차이: Length op의 MaxLength를 녹화본의 고정 "5mm" 대신, TX·RX 트레이스 너비 절반의 최솟값으로 형상에 맞춰 잡는 적응형 값으로 바꾼다.

0.3.9.3 갱신: 3 mm 하한(floor)을 제거했다. 작은 코일에선 floor가 트레이스보다 굵은 메시를 강제해 solve가 깨졌다. 규칙은 이제 floor 없는 min(tx/2, rx/2)다.

1. 규칙 — MaxLength 유일한 변경점

두 코일 트레이스 너비 절반의 최솟값을 쓴다(0.3.9.3: floor 제거).

MaxLength_mm = min( tx_trace_width_mm / 2, rx_trace_width_mm / 2 )
  • min(너비 절반) = 더 가는 코일 기준으로 폭 방향 최소 2셀 보장 → 표면 전류·근접 효과 해상.
  • floor 없음 = 작은 코일도 트레이스에 맞춰 메시가 가늘어진다. 3 mm 하한은 트레이스보다 큰 셀을 강제해 solve를 깨뜨려 0.3.9.3에서 제거.
트레이스 너비는 근사라도 무방(요구사항). 정확값이 아니라 메시 셀 상한을 잡는 용도이므로, 몇 % 오차는 패스 수렴이 흡수한다. 나머지 메시·setup·sweep 값은 §2의 녹화본을 그대로 따른다.

3. 트레이스 너비 출처 — 죽은 코드 말고 실제 빌더 경로

너비의 SSOT는 실제 STEP을 만드는 coilmaker 경로다. ssw_step._coil_boxes()는 빌드에 쓰이지 않는 구버전이므로 쓰지 않는다.

period_mm = coilmaker.ssw_active_surface_perimeter(config, frame) # 감기는 단면 둘레 pitch_mm = period_mm / ssw_turn trace_width_mm = pitch_mm * (1 - gap_ratio) # == coilmaker._ssw_trace_context(config, frame).trace_width_mm
  • SSW는 동심 루프가 아니라 단면 둘레를 따라 트레이스를 감는다 → pitch는 둘레/turn 기반.
  • 참조: src/peetsfea/coilmaker.py _ssw_trace_context() (≈ line 1520-1536).
  • 이 값은 빌더가 실제로 트레이스를 만들 때 쓰는 값과 동일(근사 아님).

4. 현재 fixed.toml 기준 수치 확인

0.3.x_fixed.toml 예시점에서 규칙을 적용했을 때의 값. 현재 형상은 충분히 커서 floor가 걸리지 않고 RX 절반이 채택된다.

코일trace_width (mm)width/2 (mm)
TX≈ 13.09≈ 6.54
RX≈ 8.93≈ 4.47
MaxLength = max( min(6.54, 4.47), 3.0 ) = max(4.47, 3.0) = 4.47 mm
즉 현재 형상에선 MaxLength가 녹화본의 5 mm → ≈ 4.47 mm로 거의 동일(살짝 촘촘). 트레이스가 작아져 RX 절반이 3 mm 밑으로 내려가면 그때부터 3 mm에서 고정된다(위로 클램프).

5. 구현 범위 (다음 작업 — 본 문서는 계획만)

코드
  • ssw_ports.py: 메시·setup·sweep 상수를 §2 녹화본 값으로 맞춤 (NumMaxElem 20000, 패스 16/16/16, PerRefine 20, MaxDeltaS 0.003, sweep 81 LinearCount …).
  • MESH_MAX_LENGTH 고정 상수를 제거/대체하고, max(min(tx/2, rx/2), 3mm)를 계산하는 헬퍼로 대체.
  • 트레이스 너비는 coilmaker._ssw_trace_context(...).trace_width_mm에서 가져온다(SSOT 단일화).
  • 계산 결과를 "<x>mm" 문자열로 mesh payload(max_length)에 주입, mesh summary(dict)의 max_length로도 노출 → 빌드 로그에서 검증.
테스트
  • test_ssw_ports.py: 현재 형상에서 max_length ≈ "4.47mm"(RX 절반) 가드.
  • 작은 형상(트레이스 너비 < 6 mm) 합성 케이스에서 floor가 걸려 "3mm"로 고정되는지 확인.
  • 패스/NumMaxElem 등 §2 값 반영 여부 가드 갱신, real headless AEDT 빌드 1회로 payload 확인.
버전: solver 튜닝(메시·패스·sweep)만 바뀌고 design space/형상은 불변 → 패키지 버전만 0.3.9.2로 bump, spec_version은 0.3.9.0 유지.

6. 근거 / 트레이드오프

  • 왜 절반? 트레이스 폭에 최소 2셀 → 표면 전류 분포의 1차 변화는 잡되 과메싱은 피함.
  • 왜 3 mm 하한? 트레이스가 작아질수록 너비/2도 작아지는데, 그대로 두면 셀이 과하게 가늘어져 element가 폭증하고 solve가 느려진다. 3 mm에서 멈춰 비용을 막는다.
  • 왜 TX·RX 둘 다(min)? 메시 op는 두 코일 + FR4에 공통 적용 → 더 가는 쪽(=더 작은 너비) 기준이어야 양쪽 모두 충분히 해상.
  • 비용: 현재 형상은 녹화본 5 mm와 거의 같은 4.47 mm라 영향 미미. 형상이 작아져 floor(3 mm)에 닿으면 더는 가늘어지지 않아 비용 상한이 고정된다.
