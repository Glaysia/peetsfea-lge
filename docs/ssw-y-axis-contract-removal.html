SSW "긴 변 = Y축" 규약은 잘못 생긴 것 — 0.3.8.0에서 제거

TX/RX SSW 코일의 긴 변이 Y축을 따라야 한다는 _validate_scene_contract의 raise 규약은 내가 width/height를 정의할 때 말을 헷갈리게 해서 생긴 의도치 않은 제약이다. 실제로는 필요 없는 규약이며 0.3.8.0부터 제거·적용한다.

1. 증상 — 형상 생성이 막힘 ValueError

현재 0.3.x_fixed.toml 값으로 STEP/AEDT를 생성하면 scene 계약 검증에서 예외가 난다.

ValueError: TX SSW long dimension must follow Y axis (size_x=180.11192, size_y=162.3146)
위치
  • src/peetsfea/ssw_step.py · _validate_scene_contract()
  • TX: if tx_bounds.size_y <= tx_bounds.size_x: raise ValueError(...)
  • RX: if rx_bounds.size_y <= rx_bounds.size_z: raise ValueError(...)
즉 "TX는 Y가 X보다, RX는 Y가 Z보다 반드시 더 길어야 한다"를 강제한다. 현재 설계는 TX의 X(180.11mm)가 Y(162.31mm)보다 길어서 이 규약을 위반 → 생성 중단.

2. 원인 — 내 width/height 정의가 헷갈리게 만든 규약

이 규약은 물리적으로 요구되는 게 아니라, 내가 "width/height"를 설명할 때 축 방향을 헷갈리게 말해서 그 의미를 코드 계약으로 굳혀버린 결과다.

무엇이 잘못됐나
  • 당시 width/height의 축 대응을 모호하게 정의 → "긴 쪽이 Y를 따라야 한다"는 방향 가정이 끼어듦.
  • 그 가정이 형상 검증의 hard raise로 들어가, 설계 자유도를 부당하게 제약.
  • 결과: width/height 비율을 자유롭게 바꾸면 (긴 변이 X로 가는 순간) 합법적인 코일인데도 생성이 막힘.
왜 필요 없나
  • SSW 코일의 긴 변이 X냐 Y냐는 해석 정확성·물리와 무관(좌표축은 임의 라벨).
  • 포트/페라이트/메시는 모두 코일에 상대적으로 정의되므로 절대 축 방향에 의존하지 않는다.
  • thin-Z(TX)·thin-X(RX) 같은 "평면성" 검증은 의미 있지만, "어느 변이 더 길어야 한다"는 불필요.

3. 설계 원칙 위반 — 이건 raise가 아니라 toml constraints였어야

설령 이런 제약이 정말 필요했더라도, 형상 빌더 한복판에서 raise ValueError로 막는 건 잘못된 자리다.

  • 진짜 제약이라면 데이터(설계공간)에 선언했어야 한다 — toml의 constraints로. 그래야 샘플러가 생성 단계에서 위반 조합을 애초에 안 뽑고, 설계공간 문서에도 드러난다.
  • raise는 이미 만들어진 형상을 사후에 거부할 뿐 — 낭비(생성→폐기)이고, 설계공간엔 보이지 않는 숨은 규약이 된다.
  • 즉 "constraints로 선언 안 하고 raise로 막았다" = 이 규약이 원래 의도된 설계 제약이 아니었다는 방증.
정리: 필요한 제약 → toml constraints(선언적, 샘플링 단계). 불변식 검증 → 평면성 같은 물리적으로 의미 있는 것만. "긴 변 = Y"는 둘 다 아니므로 그냥 제거한다.

4. 조치 0.3.8.0

버전상태내용
0.3.7.1과거 임시 STEP/AEDT를 보기 위해 TX·RX "긴 변 = Y" 두 raise를 임시 비활성화(주석+pass).
0.3.8.0제거·적용 두 "긴 변 = Y축" 규약을 코드에서 완전히 삭제. 평면성(thin-Z/thin-X) 검증은 유지. 만약 향후 실제 방향 제약이 필요해지면 raise가 아니라 toml constraints로 선언.
요지: 이 규약은 내 용어 혼동에서 비롯된 원치 않은 제약이고, 필요도 없으며, 자리(코드 raise)도 틀렸다 → 0.3.8.0에서 제거한다.
