SSW solve 비용 계획 — skin-depth 메시 되돌리고 코어 16 (0.3.9.1)

0.3.8.3에서 넣은 구리 skin-depth 메시가 초기 메시 element를 ~15만 개로 폭증시켜 solve가 비정상적으로 오래 걸린다. GUI 실험(mesh_pass.py)에서 단일 length 메시(15k, skin-depth 없음)는 adaptive 25패스를 돌려도 오히려 훨씬 빨리 끝났다. 따라서 ① skin-depth 메시를 가벼운 length 메시로 되돌리고, ② solver 코어를 4 → 16으로 늘린다.

1. 문제 — skin-depth 메시가 초기 element를 폭증시켜 느림 regression

0.3.8.3의 CopperSkinDepth op(25µm, 4 layers)은 구리 표면을 과하게 잘게 쪼개 adaptive가 시작하기도 전의 초기 메시를 수십만 tet로 만든다. 이후 모든 패스가 그 큰 메시 위에서 도므로 패스당 시간이 급증한다.

[관측] skin-depth 빌드 solve 프로파일 Initial Meshing → Tetrahedra: 206,504 (Length1 + SkinDepth1) Adaptive Meshing: 00:16:32 · Frequency Sweep: 00:30:06 · 합계 ≈ 00:46:52
핵심: 시작 element가 ~15만~20만이면 adaptive 첫 패스부터 메모리·시간이 폭증한다. skin-depth는 "정확도엔 이론적으로 맞는" 선택이지만, 이 형상·주파수(6.78MHz)에선 비용이 정확도 이득을 압도한다.

2. 근거 — 가벼운 메시 + 많은 패스가 더 빠름 GUI 실험

0622_3를 AEDT GUI에서 직접 수정·녹화한 mesh_pass.py는 메시를 단순화하고 패스를 늘렸는데도 실측이 훨씬 빨랐다.

현재 코드 (0.3.8.3)
  • 메시: CopperSkinDepth(50000, 25µm, 4 layers) + DielectricMesh(50000, 1mm)
  • 초기 element: ~15만+ (skin-depth가 지배)
  • 패스: 16 / 9 / 4, refine 26%
  • 실측: 느림 (초기 메시가 무거워 패스마다 비쌈)
녹화 실험 (mesh_pass.py)
  • 메시: 단일 Length1, NumMaxElem 15000, 1mm, skin-depth 없음
  • 초기 element: ~1.5만 (10배 작게 시작)
  • 패스: 녹화 25 / 25 / 5 → 계획 25 / 23 / 5 (max 25, min 23, conv 5; min을 23으로 낮춰 조기수렴 여지), refine 25%
  • 실측: 훨씬 빨리 끝남 ← 작게 시작해서 adaptive가 필요한 곳만 키움
교훈: "작게 시작해서 adaptive가 키우게" 두는 편이, "처음부터 skin-depth로 크게 깔고 시작"하는 것보다 빠르다. HFSS adaptive는 어차피 필요한 곳을 refine하므로, 시작 메시를 인위적으로 부풀릴 이유가 약하다.

3. 계획 ① — skin-depth 메시를 가벼운 length 메시로 되돌림 0.3.9.1

0.3.8.3에서 도입한 2-op 구조(skin-depth + dielectric)를 되돌려, 초기 element를 낮춘다.

항목현재 (0.3.8.3)계획 (0.3.9.1)
구리 메시 opAssignSkinDepthOp (25µm / 4 layers)제거 → length 기반으로 통합
메시 구조CopperSkinDepth + DielectricMesh단일 length op (구리+유전체) 또는 경량 2-op
NumMaxElem5000015000 (실험치)
MaxLength1mm1mm (유지)
변경 대상
  • src/peetsfea/backend/pyaedt/ssw_ports.py — _assign_recorded_mesh, _copper_mesh_payload/_dielectric_mesh_payload, MESH_MAX_ELEMENTS(50000→15000), skin-depth 상수 제거
  • SswAedtMeshSummary / MeshModuleSession(AssignSkinDepthOp) 정리 — 0.3.8.3 변경의 역작업
  • 관련 테스트(test_ssw_ports.py) mesh 단언 갱신
정확도 측면: skin-depth를 빼면 구리 표피 해상도는 adaptive refinement에 맡긴다. 6.78MHz 표피깊이 ~25µm는 Rac/Q에 영향을 주므로, 제거 후 후속 측정에서 L/R/Q가 허용 오차 안인지 반드시 확인한다(아래 §5).

4. 계획 ② — solver 코어 4 → 16 0.3.9.1

0.3.7.1에서 동시 solve 경합을 막으려 코어를 4로 고정했는데, 단일 solve를 빠르게 돌리려면 코어를 늘린다.

상수위치현재계획
FORCED_SOLVE_CORESsrc/peetsfea/aedt/wrappers.py416
SOLVE_CORESsrc/peetsfea/backend/pyaedt/ssw_ports.py416
주의: 코어 16은 단일 solve를 빠르게 하지만, N개 동시 solve를 돌리면 다시 경합한다(0.3.7.1가 막으려던 문제). 병렬 샘플링 시에는 동시 solve 수를 줄이거나 코어를 나눠야 한다 — 16코어는 1개씩 돌릴 때 최적.

5. 검증·측정 계획

  • 속도: 같은 fixed TOML·seed로 (a) 현재 skin-depth 4코어 vs (b) 경량 메시 16코어 solve 시간 비교. profile의 Initial Meshing tet 수와 Adaptive/Sweep elapsed를 기록.
  • 정확도: skin-depth 제거 전후 Results3_Freq의 L_tx/L_rx/Q, Results1_Pass의 reZ(저항)를 비교 — 구리 손실(Rac)이 허용 오차 내인지 확인.
  • 회귀 방지: 초기 메시 element 수를 ledger/telemetry에 남겨, 다시 폭증하면 바로 보이게 한다.
  • pure-Python tests, pyright, real headless AEDT validation 통과.
버전: 설계공간(geometry SSOT)은 안 바뀌므로 spec_version은 0.3.9.0 유지, 패키지 버전만 0.3.9.1로 올린다(솔버 비용 튜닝 — 0.3.8.1~0.3.8.3 선례와 동일).
